# Security policy

## Секреты

В репозитории запрещено хранить:

- файлы `.env` с реальными значениями;
- пароли PostgreSQL;
- JWT/refresh tokens и коды приглашений;
- SSH, TLS, Android signing и другие private keys;
- IP-адреса инфраструктуры, если они не нужны публичному контракту;
- production dumps, пользовательские email и другие персональные данные.

В коде и миграциях refresh tokens и invite codes представлены только
криптографическими хэшами. Пароли будут храниться только как Argon2id encoded
hash после реализации auth.

## Перед commit

1. Выполнить `git status --short`.
2. Просмотреть `git diff --cached`.
3. Убедиться, что `.env`, ключи, логи, дампы и IDE metadata отсутствуют.
4. Выполнить `.\gradlew.bat clean test`.

Если секрет попал в Git, одного удаления файла недостаточно: секрет нужно
немедленно отозвать/заменить и очистить историю отдельной контролируемой
операцией.

## Уязвимости

Не публикуйте рабочие секреты и эксплуатационные детали в public issue.
Сообщение владельцу репозитория следует отправлять приватным каналом через
профиль GitHub. До появления отдельного security contact публичные issue
используются только для проблем без чувствительных данных.
